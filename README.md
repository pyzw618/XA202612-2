# OS Agent 记忆引擎底层架构

本项目实现了基于麒麟操作系统的 OS Agent 记忆优化系统的核心底层引擎：**端侧轻量化混合检索与记忆流转架构**。

## 一、 memory_store.py
**整个记忆系统的“Mock 数据存储中心（数据库底座）”**

### 1.1 主要工作目的
把原始文字、SDK翻译出来的数字向量、以及时间标签，统统打包存起来并进行统一管理。

### 1.2 核心数据结构 —— `MemoryRecord` 类
记录单条记忆内容：
- **`id`**: 给每一条记忆生成一个不重复的 12 位字符串。未来执行“精准遗忘操作”（赛题要求5），就是靠这个 ID 去指名道姓地删除。
- **`content`**: 存用户说的话。BM25 关键词检索就是对着这个字段查的。
- **`embedding`**: 留给麒麟 Embedding SDK 的坑位！SDK 算出来的向量数组就塞进这里。FAISS 向量检索就是对着这个字段查的。
- **`created_at`**: 自动记录记忆产生的时间。未来做“中短期记忆淘汰流转”（赛题要求6）就是靠对比这个时间戳。
- **`metadata`**: 极度灵活的字典标签。可以往里面塞 `{"type": "偏好", "level": "短期"}`，方便后续精准过滤。

### 1.3 存储管理结构 —— `MemoryStore` 类
- **初始化与增加**: 目前用一个列表当做假数据库。
- **查找**: 当 FAISS 或 BM25 告诉你“ID 为 1234 的记忆最匹配”时，通过这个方法把对应的原始文本拿出来喂给大模型。
- **删除**: 找到指定的 ID，把它从档案柜里抽出来销毁。

## 二、 mock_embedding.py
**模拟的麒麟 Embedding 翻译官**

- **主要工作目的**: 模拟真实 SDK。给它输入一段文字，它假装思考 0.1 秒，然后吐出一个包含 768 个小数的随机数组。
- **确定性随机**: 通过哈希函数，使得相同文本无论调用多少次，生成的随机数组都是一模一样的。
- **批量处理**: 模拟了硬件底层的“批处理加速”。处理 1 条和处理 50 条，系统只消耗一次 100ms 延迟。

## 三、 search_engine.py
**解决端侧轻量化环境中，实现高召回率（≥85%）的检索 —— 混合检索 (Hybrid Search)**

### 3.1 简易分词器 (`_simple_tokenize`)
把一整句话切成一个个词或字，这是给 BM25 用的。

### 3.2 BM25 检索器 (`BM25Retriever`)
- **底层依赖**: 用了 `rank_bm25` 这个极其轻量的 Python 库。
- **核心逻辑**: 算出 TF-IDF 升级版的分数。匹配的关键词越多、越稀有，分数就越高（比如 15.6 分，22.1 分）。

### 3.3 FAISS 检索器 (`FaissRetriever`)
- **底层依赖**: Meta 开源的 `faiss-cpu`。这是目前单机端侧跑得最快的向量检索引擎，占内存极小。
