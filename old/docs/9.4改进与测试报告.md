# 9.4 改进与测试报告

## 1. 交付范围

本次改进对应 `9.4问题.md` 中的四项要求，发布目标为 Kylin MemoryHub
`0.1.0-12`（amd64）：

1. 修复总览页“记忆构成对比”柱状图，增强柱状图和饼图的可读性。
2. 统一桌面端、命令行、OpenCode 插件和 MCP 的用户身份，默认使用当前 Linux
   登录用户，并提供 `global` 全局用户。
3. 在总览页提供“一键配置”，用于在后安装 OpenCode 时重新配置集成。
4. 在总览页提供“打开 Agent”，从用户主目录打开终端并启动 OpenCode。

## 2. 实现结果

### 2.1 总览图表

- “记忆构成对比”改为五类独立数据组，避免原数据形状导致柱体不显示。
- Y 轴根据实际数据动态计算范围。
- 柱状图增加数值标签、入场动画和统一配色。
- 饼图增加渐变色、悬停突出和标签，空数据时仍保持清晰的占位状态。

### 2.2 用户身份

- 桌面端从系统会话检测当前 Linux 用户，不再固定使用 `default`。
- 左下角仅提供“当前用户”和“全局用户”两个清晰入口。
- CLI、OpenCode 插件和 MCP 默认使用当前系统用户。
- 写入、查询、更新、删除和遗忘操作均使用当前选中的用户，防止跨用户串写。

### 2.3 OpenCode 一键配置

- “一键配置”会把插件、命令、技能和工具文件同步到当前用户的
  `~/.config/opencode`。
- 同时生成 `~/.config/memoryhub/config.json`，其中 `user_id` 为当前 Linux 用户。
- 配置操作不再启用旧版 `memoryhub.service`，避免重新引入升级后的残留服务。

### 2.4 打开 Agent

- 自动检测 UKUI、MATE、GNOME、Konsole 等常见图形终端。
- 新终端的工作目录为当前用户主目录。
- 已安装 OpenCode 时自动运行；未安装时给出明确提示并保留可用 Shell。

### 2.5 图形升级可靠性

- 图形启动器在升级时会检查安装版本、服务 PID、进程所有者和完整命令行。
- 发现旧版本后会停止当前用户的全部 MemoryHub 残留服务。
- 只有新服务真正通过健康检查后才写入版本和 PID 标记，避免端口绑定失败却被
  误判为升级成功。
- 事件写入异常会记录服务端堆栈，同时对客户端继续返回稳定、无敏感信息的错误。
