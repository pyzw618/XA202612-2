# 新旧知识冲突处理实验指南

本文档面向“新旧知识冲突处理正确率 > 88%”这一指标，说明当前代码如何运行、如何评测，以及后续如何升级到更强算法。

## 1. 模块目标

在 OS Agent 记忆写入阶段，新知识不能简单追加到记忆库中，而应先和旧知识比较：

```text
新知识进入
  ↓
检索同主题旧知识
  ↓
判断 conflict / consistent / unrelated
  ↓
冲突则替换、降权、归档或人工复核
  ↓
无冲突则合并或保留
```

当前实现位于：

```text
memory_core/conflict/
```

核心类：

```python
from knowledge_conflict import KnowledgeConflictDetector

detector = KnowledgeConflictDetector()
result = detector.detect(old_item, new_item)
```

输出标签：

| 标签 | 含义 | 写入策略 |
|---|---|---|
| `conflict` | 新旧知识同主题但矛盾 | 替换旧知识或进入人工复核 |
| `consistent` | 新旧知识一致或互相补充 | 合并证据、提高置信度 |
| `unrelated` | 不是同一事实或适用场景不同 | 保留两条记忆 |

## 2. 当前算法

当前是轻量级混合规则基线，不依赖外部模型，适合先在银河麒麟虚拟机里跑通。

使用的信号包括：

1. 结构化元数据：`entity`、`attribute`、`scope`；
2. 日期冲突：例如截止时间从 5 月 15 日改到 5 月 20 日；
3. 数值冲突：例如响应时间从 `≤500ms` 改为 `≤800ms`；
4. 状态极性冲突：例如“支持精准遗忘”变成“不支持精准遗忘”；
5. 枚举值冲突：例如 `SQLite` 替换为 `PostgreSQL`；
6. 场景隔离：例如技术报告偏好和代码偏好不直接冲突；
7. 修订意图：识别“改为、更新为、替换为、不再、延长到”等词。

## 5. 如何面向 88% 指标做实验

建议按三个阶段做。

### 阶段一：构造评测集

从项目真实材料、工具调用日志、组内讨论记录中整理三类样本：

| 类别 | 说明 | 例子 |
|---|---|---|
| conflict | 同一事实发生矛盾或版本更新 | 截止时间、部署方式、存储方案改变 |
| consistent | 同一事实一致或补充 | 都说明检索延迟 ≤500ms |
| unrelated | 主题不同或适用场景不同 | PPT 偏好 vs 检索算法 |

推荐至少：

```text
conflict: 100 条
consistent: 80 条
unrelated: 80 条
```

每条样本格式：

```json
{
  "id": "case_001",
  "label": "conflict",
  "type": "date",
  "old": {
    "text": "项目报名截止时间是2026年5月15日16:00。",
    "entity": "报名",
    "attribute": "deadline"
  },
  "new": {
    "text": "老师通知报名截止时间延长到2026年5月20日16:00。",
    "entity": "报名",
    "attribute": "deadline"
  }
}
```

### 阶段二：结构化抽取

不要只把原始句子丢给冲突检测器。记忆写入前应先抽取：

```text
entity: 知识所属对象
attribute: 属性类型
scope: 适用场景
value: 结构化值
source: 来源
timestamp: 时间
confidence: 置信度
```

冲突检测正确率要超过 88%，关键不是只靠一个分类器，而是先把记忆结构化。

### 阶段三：对比实验

建议做四组实验：

| 实验 | 方法 | 目的 |
|---|---|---|
| E1 | 只用文本相似度 | 最弱 baseline |
| E2 | 规则冲突检测 | 日期、数值、状态、枚举 |
| E3 | 结构化元数据 + 规则 | 当前代码主方案 |
| E4 | E3 + NLI/LLM 判别 | 后续增强方案 |

最终报告中可以写：

```text
在自建新旧知识冲突评测集上，结构化元数据 + 混合规则检测方法达到 xx% 正确率，
相比纯文本相似度 baseline 提升 xx 个百分点。
```

## 6. 如何进一步提升到官方数据集

如果组内或官方评测集更复杂，建议增强以下部分：

1. 加入中文 NLI 模型，判断 entailment / contradiction / neutral；
2. 对时间、数值、版本号、指标阈值做更细粒度归一化；
3. 给记忆增加 `source_trust`，例如老师通知 > 用户猜测 > 模型生成；
4. 增加 `scope` 判定，避免不同场景偏好误判冲突；
5. 引入主动学习，把错例回流到规则表和训练集；
6. 对 `conflict_type` 分桶统计，优先修复日期、数值、策略类高频错例。

可以在报告里这样写：

```text
针对新旧知识冲突处理正确率 ≥88% 的指标，我们将冲突检测建模为三分类任务：
conflict、consistent、unrelated。系统在记忆写入阶段先进行结构化抽取，
得到 entity、attribute、scope、value 等字段，再结合日期差异、数值约束差异、

后续将接入中文 NLI 模型和来源可信度评分进一步提升复杂语义冲突的识别能力。
```
