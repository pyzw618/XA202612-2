# 前端遗忘子菜单设计参考

> 2026-08-04

---

## 一、设计思路

后端遗忘模块按 **显式 / 自动 / 被动** 三种遗忘场景实现，前端子菜单按 **「操作 → 审查 → 归档 → 回收 → 看板 → 历史 → 设置」** 的用户动线组织，把技术场景翻译成用户可理解的入口，而不是暴露技术术语。

## 二、推荐结构（7 项）

```
▸ 遗忘管理                     [琥珀 ● #F59E0B]
  │
  ├─ 精准遗忘        ●主操作    显式遗忘：按 ID / 范围 / 自然语言三种方式，先出候选列表、确认后执行
  ├─ 待审查队列      ●红        自动遗忘标记 pending（健康度 0.4~0.6）的记忆，人工裁决去留
  ├─ 归档仓库        ●灰        健康度 <0.2 自动归档的记忆，可查看、可解除归档
  ├─ 回收站          ●绿        软删除（status=deleted）的记忆，可一键恢复
  ├─ 健康度看板      ●青        健康度分布、衰减趋势、"即将被遗忘"预警
  ├─ 遗忘历史        ●蓝        审计日志：谁 / 何时 / 忘了什么 / 删了几条
  └─ 遗忘设置        ●紫        阈值、权重、定时扫描开关
```

## 三、各子页该放的按钮

### ① 精准遗忘（核心页，对应 `MemoryForgetter` 三种模式）

- 模式切换 Tab：`自然语言` | `按范围` | `按 ID`
- 输入区：指令输入框 / 场景范围选择器（scene·task_type·app）/ ID 列表
- 级联开关：`是否级联清理`（向量索引、缓存、证据链）
- 候选确认：`匹配到 N 条` → 展示候选 → `确认遗忘` / `取消`
- 结果反馈：删除条数 + 审计记录号

### ② 待审查队列

- 列表：记忆内容 / 健康度 / 降级建议
- 行操作：`保持` | `降级` | `归档` | `删除`
- 批量：`全部保持` / `全部归档`

### ③ 归档仓库

- 列表 + 详情；操作：`解除归档` / `删除`

### ④ 回收站

- 软删除列表；操作：`恢复` | `彻底删除`（物理清理，需二次确认）

### ⑤ 健康度看板

- 健康度分布直方图（4 个区间 `<0.2 / 0.2-0.4 / 0.4-0.6 / ≥0.6`）
- 近 30 天衰减最快的 Top N 列表
- 单条记忆明细：时间衰减分 / 使用频率 / stability


### ⑦ 遗忘设置

- 健康度权重：时间衰减 0.6 / 使用频率 0.4（滑动条）
- 阈值：归档 0.2 / 降级 0.4 / 待审 0.6
- 自动遗忘：`开启定时扫描` + 扫描周期
- 被动遗忘：重排序健康度权重（当前 0.1）

## 四、与后端 API 对应 + 现状

| 子菜单 | 依赖 API | 后端现状 |
|---|---|---|
| 精准遗忘 | `POST /api/memory/forget` | ✅ 已实现（NL 为规则版，候选确认未做） |
| 待审查队列 | `GET /forget/pending` | 🚧 待补 |
| 归档仓库 | `GET /forget/archived` + 解除 | 🚧 待补 |
| 回收站 | `GET /forget/deleted` + restore | 🚧 待补 |
| 健康度看板 | `POST /api/memory/health` | ❌ 未实现（文档已列为待办） |
| 遗忘设置 | `POST /forget/settings` | 🚧 待补 |

## 五、PyQt6 实现要点（对齐现有风格）

- 点击"遗忘管理"展开/收起子菜单，子项选中高亮、右侧切换页面
- 子项圆点用琥珀同色系浅色即可，只有 `待审查队列` 用红色制造"需要处理"的注意力点
- 子项比一级项缩进 ~16px、字号小一号（10pt），与现有 `sidebar.py` 的 44px 高按钮区分

## 六、落地建议

如果第一版想快速出东西，可以先只做 **`精准遗忘` + `待审查队列` + `遗忘历史`** 三项（前端能跑通、后端已有接口），其余四项（归档 / 回收站 / 健康度 / 设置）等后端 API 补上后再挂菜单。
