# 事实冲突类型与处理矩阵

## 当前交互原则

显式事实采用两阶段确认：主 Agent 调用 `memoryhub_propose_facts` 后必须先让用户选择
`commit/reject`；用户选择提交后，MemoryHub 才执行归一化与冲突检测。若出现歧义或冲突，
系统再次返回 `decision_task`，由主 Agent展示新旧信息并询问用户，再调用
`memoryhub_decide_facts` 完成裁决。

自动事件抽取仍可由系统策略产生候选，但不能绕过安全门禁、用户隔离和冲突检测。

## 冲突与等价类型

| 类型 | 示例 | 当前处理 |
|---|---|---|
| 直接重复 | A 的生日是 6 月 6 日；再次写入相同内容 | 归一化后判定 `DUPLICATE` |
| 主体单值冲突 | A 的生日是 6 月 6 日 / 7 月 1 日 | `subject_cardinality`，请求用户裁决 |
| 逆关系等价 | A 是 B 的儿子 / B 是 A 的父亲 | `inverse_equivalent`，视为同一关系 |
| 逆向单值冲突 | A 的父亲是 B / A 的父亲是 C | `object_cardinality` 或主体单值冲突 |
| 对称关系等价 | A 是 B 的配偶 / B 是 A 的配偶 | `symmetric_equivalent` |
| 对称关系基数冲突 | A 的配偶是 B / A 的配偶是 C | 基数冲突，请求用户裁决 |
| 互斥谓词 | A 健在 / A 已故 | `mutually_exclusive_predicate` |
| 自反非法 | A 是 A 的父亲；模块属于自身 | `irreflexive_violation` |
| 关系环 | A 属于 B、B 属于 C、C 属于 A | `relation_cycle` |
| 主体类型不符 | “文件”担任某公司 CEO | `domain_type_violation` |
| 客体类型不符 | 总部所在地被写成“软件” | `range_type_violation` |
| 多值共存 | 公司创始人是 A；公司创始人也是 B | `COEXIST` |
| 作用域差异 | 全局负责人 A；项目 X 负责人 B | 分别保存在 GLOBAL/PROJECT，不直接互相覆盖 |

本体当前预置家庭关系、配偶/兄弟姐妹、雇佣、成员、所有权、上下级、组成关系以及
健在/已故互斥关系。新增业务关系时应在 `predicate_ontology.json` 中声明别名、domain、
range、单值性、逆关系、对称性、互斥性、非自反性与无环约束。

## 需要后续数据模型支持的类型

以下问题不能只靠普通三元组可靠解决，本轮不做错误的强判定，而是保留为后续扩展：

- 时间区间：同一职位在不同任期、同一地点在不同日期可能都成立；需要 `valid_from/valid_to`。
- 否定、模态与不确定性：“不是”“可能是”“曾经是”；需要 polarity/modality 字段。
- 数值、单位与区间：1000 米与 1 公里、约 10 人与 12 人；需要类型化值和单位换算。
- 传递与派生关系：A 位于 B、B 位于 C，不等于原文直接声称 A 位于 C；应区分原始与推导事实。
- 多元关系：某人在某项目中担任某角色，不能丢失项目、时间等限定条件。
- 身份合并与拆分：同名不同人、改名、组织并购；歧义继续交给主 Agent或用户确认。
- 来源可信度冲突：来源权威性只能辅助用户决策，不能静默覆盖明确事实。
- 并发写入：多个 Agent 同时修改同一事实时，需要乐观锁或事务版本号。

## 记忆分类边界

- **事实**：描述“谁/什么是什么、有什么、在哪里、与谁有什么关系”，包括用户画像中的身份、
  生日、家人、设备、账户、地点、任职、所有权和项目角色。
- **偏好**：描述 Agent 应该“怎么做”，例如输出格式、语言、工具、流程和安全选择。
- **知识**：与某个用户属性无关、可以复用的工作流、案例或模板。

当一句话同时包含事实和偏好时，主 Agent应拆成两个独立候选，分别调用事实与偏好工具，
不能把整句都归入偏好。
