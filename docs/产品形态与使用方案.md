## 1. 产品定位与价值主张

### 1.1 一句话定位

> **MemoryHub 是运行在银河麒麟 OS 上的端侧 AI Agent 记忆引擎 —— 让系统级 Agent 记住用户的偏好、学到可复用的工作流、沉淀事实知识，并在后续交互中自动复用。**

### 1.2 解决的核心问题

| 问题 | 现状 | MemoryHub 的解法 |
|---|---|---|
| **会话无记忆** | Agent 每次交互从零开始，用户偏好和已学流程无法跨会话复用 | 持久化三类记忆：偏好 / 知识 / 事实，混合检索自动召回 |
| **记忆孤岛** | 每个 Agent 各存各的，无法共享、无法统一管理 | 单一记忆底座 + MCP/REST 标准接入，多 Agent 共享同一份记忆 |
| **记忆不可见不可控** | 记忆黑盒，用户不知道存了什么，也无法遗忘 | 桌面控制台可视化 + 精准遗忘 + 生命周期自动清理 |
| **数据安全无保障** | 记忆可能含敏感信息，无门禁无审计 | 内置安全门禁、审计哈希链（需开启）、REVIEW 隔离区（需开启）、用户敏感规则 |

### 1.3 价值主张（三层对象）

| 对象 | 价值 |
|---|---|
| **OS 终端用户** | Agent 越用越懂你：记住偏好、复用工作流、减少重复操作；记忆可查看、可控制、可一键遗忘 |
| **Agent 集成方 / 开发者** | 标准接入（MCP/REST），一次集成获得完整记忆能力，无需自研存储/检索/生命周期/安全 |
| **OS 平台 / 运维** | 端侧部署，记忆数据不出机器；统一安全门禁与审计；可视化控制台运维调参 |

### 1.4 与主流方案的差异化定位

与 Mem0 / Letta / LangMem / Zep 等面向开发者的记忆平台不同，MemoryHub 的独特定位是：

> **OS 级、端侧、多 Agent 共享的记忆底座** —— 随操作系统预装，作为系统级 Agent 的基础能力，而非一个需要开发者单独采购/部署的 SaaS 或 SDK。（详细对照见[第 8 章](#8-关键设计决策与主流方案对照)）

### 1.5 现状与最终形态：先校准预期

> 本文档描述的"最终形态"是**目标**，并非今天全部可用。为避免误读，先用一张表明确"现在能跑什么"与"最终交付什么"的差距：

| 维度 | 今天（当前基线 @ `8c04b4d`） | 最终形态 |
|---|---|---|
| 运行栈 | **源码/pip + Mock Embedding + FAISS**（开发/测试栈） | 麒麟 Embedding SDK + Milvus（生产栈，规划中） |
| 记忆内核能力 | 全链路已实现：摄取→安全→抽取→存储→混合检索→冲突→遗忘/生命周期 | 同左 + 生产级调优 |
| 抽取实现 | 无真实 LLM 时走确定性规则/降级路径，失败进入重试队列 | 接入真实 LLM 的抽取质量优化（规划中） |
| 获取渠道 | **开发者源码/pip + x86_64 DEB 独立安装包**；RPM、arm64 与签名发布尚未完成 | OS 预装（主）+ 多架构独立安装包 |
| 桌面控制台 | ✅ 21 页 9 模块可用 | 同左 |
| Agent 接入 | ✅ MCP 12 工具 × 3 套集成可用 | 同左 + 更多 Agent 集成 |
| 安全 | 能力已实现；审计/隔离区默认关 | 生产默认开启（规划中） |
| 评测 | 检索评测完成；偏好/冲突评测为框架占位 | 全部补全 |

**结论：今天即可通过「开发者渠道 + 开发栈」完整体验记忆全链路；生产化（麒麟 SDK/Milvus、OS 预装、安装包、安全默认开启）是 P1–P2 的工作。**

## 2. 目标用户与使用场景

产品以**最终用户**为核心服务对象，开发集成方与运维审计作为支撑角色。

### 2.1 角色 1：OS 终端用户（主要）

通过系统级 Agent（内置助手 / 终端 Agent 如 opencode）的自然语言对话**间接**使用记忆能力。

| 场景 | 例子 | 支撑能力 |
|---|---|---|
| **偏好记忆** | "以后周报都用 Markdown 格式" → 之后每次生成周报自动用 Markdown | 偏好抽取 + 检索注入 |
| **工作流复用** | 完成一次"批量重命名→压缩→上传"后，下次一句话触发整条流程 | 知识（workflow）抽取 + 复用 |
| **事实记忆** | "我的邮箱是 xx@example.com" → Agent 之后记得 | 事实三元组抽取 |
| **遗忘与控制** | "忘掉我关于周报格式的偏好"；在控制台查看/删除记忆 | 精准遗忘 + 桌面控制台 |

**交互原则**：最终用户尽量不感知记忆系统本身，只感知"Agent 越来越懂我"；必要时通过 Agent 或控制台做显式控制。

> **外部依赖（前提条件）**：最终用户能否用到记忆，取决于麒麟 OS 上**已存在一个 Agent**（内置助手 / 终端 Agent 如 opencode）作为对话入口。MemoryHub 本身不提供对话界面，它是 Agent 的"记忆底座"。麒麟 OS 是否出厂预装 Agent、预装哪一个，是本文档无法自行决定的外部前提（见[第 9 章](#9-风险非目标与未决问题)未决问题）。

### 2.2 角色 2：Agent 集成方 / 开发者

将记忆能力接入自己的 Agent：

- 通过 **MCP**（Claude Code / opencode / 自研 MCP 客户端）或 **REST** 接入 12 个记忆工具；
- 部署 MemoryHub 本地服务，配置环境变量，即可获得持久记忆；
- 已有三种现成集成可参考/直接使用：Claude Code、opencode、Qwen-LangGraph。

### 2.3 角色 3：运维与审计

通过 Qt 桌面控制台（21 页 / 9 模块）完成：

- 记忆全生命周期管理（增删改查、状态流转、批量操作）；
- 事实候选裁决、冲突裁决；
- 安全审计（用户敏感规则、审计日志验链、REVIEW 隔离区）；
- 检索质量验证、遗忘设置、健康度看板、演示数据工具。

## 3. 产品形态总览

### 3.1 三层形态

```
┌──────────────────────────────────────────────────────────────────┐
│                    ①  用户交互面                                    │
│   ├─ OS Agent（最终用户自然语言入口）  ← MCP / REST / 自动沉淀       │
│   └─ Qt 桌面控制台（审计/运维/调参/演示，21 页 9 模块）              │
├──────────────────────────────────────────────────────────────────┤
│                    ②  Agent 接入层                                 │
│   ├─ MCP Server（12 工具，Claude Code / opencode 通用）            │
│   ├─ REST API（FastAPI，/api/memory/*，/api/agent/*）              │
│   └─ 自动沉淀 Hooks / Plugin（工具轨迹 → MemoryEvent）              │
├──────────────────────────────────────────────────────────────────┤
│                    ③  记忆内核服务（本地常驻）                       │
│    摄取 → 质量评分 → 安全门禁 → 抽取(偏好/知识/事实) → 存储          │
│        → 混合检索 → 冲突处理 → 遗忘 / 生命周期                       │
├──────────────────────────────────────────────────────────────────┤
│  存储层：SQLite（事实源）+ 向量索引(FAISS/Milvus) + BM25 + 证据链    │
└──────────────────────────────────────────────────────────────────┘
```

### 3.2 三个交付物

| 交付物 | 形态 | 现状 |
|---|---|---|
| **记忆内核服务** | Python/FastAPI 本地服务，`127.0.0.1:8099`；开发栈 Mock+FAISS，生产装配麒麟 Embedding SDK + Milvus | 【已实现】全链路能力；生产装配【规划中】 |
| **桌面控制台** | Qt 5 原生客户端，人工审计/演示/调参/运维 | 【已实现】21 页 9 模块 |
| **Agent 接入层** | MCP Server + REST + 自动沉淀 hooks/plugin；三套集成（Claude Code / opencode / Qwen-LangGraph） | 【已实现】各 12 个 MCP 工具 |

### 3.3 部署形态（两态并存）

- **形态 A（主）—— 随麒麟 OS 预装/出厂**：系统自带 `memoryhub` systemd 服务（常驻）+ 预装桌面控制台，用户零安装。
  - 【已实现】`packaging/linux/memoryhub.service` systemd unit 模板；`scripts/verify_kylin_environment.py` 环境自检（Embedding/向量 SDK/平台/依赖）；
  - 【规划中】预装集成流程与出厂打包。
- **形态 B —— 独立安装包**：面向已有系统的用户，提供麒麟（arm64/x86_64）`rpm`/`deb` 离线安装包，安装即得"服务 + 控制台"；Windows 安装器仅作**开发验证**用途，不属于生产交付。
  - 【已实现】桌面客户端 Linux/Windows 构建脚本（`build-linux.sh` / `build-win.ps1` / `build-windows.bat`）；
  - 【已实现】`packaging/linux/build-deb.sh` 生成 x86_64 DEB，内含离线 Python wheelhouse、Qt 控制台、systemd 用户服务，并按实际用户主目录自动配置 OpenCode 插件；
  - 【规划中】arm64/RPM、软件包签名与 OS 仓库发布。

## 4. 用户如何获取与安装

### 4.1 渠道一：随麒麟 OS 预装（出厂形态，主渠道）

- OS 出厂即包含：`memoryhub` systemd 服务 + 桌面控制台（应用菜单入口），数据目录 `~/.local/share/MemoryHub/`。
- 用户**零安装**：首次登录自动初始化本地数据库与向量索引。
- 服务常驻，监听 `127.0.0.1:8099`，仅本机 Agent/客户端访问。

```ini
# packaging/linux/memoryhub.service（已提供模板）
[Unit]
Description=MemoryHub local memory service
After=graphical-session.target

[Service]
Type=simple
WorkingDirectory=%h/.local/share/MemoryHub/app
ExecStart=%h/.local/share/MemoryHub/app/scripts/start-memoryhub-service.sh
Restart=on-failure
RestartSec=3

[Install]
WantedBy=default.target
```

### 4.2 渠道二：独立安装包（面向已有系统）

**麒麟 Linux（生产）**：

```bash
sudo apt install ./kylin-memoryhub_<version>-1_amd64.deb
# 安装器按实际用户主目录写入 ~/.config/opencode，并全局启用 systemd 用户服务。
# 当前会话如需立即初始化，可执行：
memoryhub-configure-opencode --current-user
systemctl --user status memoryhub --no-pager
# 桌面控制台从应用菜单启动（随包安装）
```

DEB 内含 Python 离线 wheelhouse，安装配置阶段不依赖 PyPI；OpenCode 插件放入官方全局插件目录 `~/.config/opencode/plugins/`，命令、技能与工具放入同一配置根目录下的复数子目录。

**Windows（仅开发验证）**：运行安装器，安装服务与客户端，用于本地联调；不面向生产分发。

### 4.3 渠道三：开发者获取（源码 / pip）

```bash
git clone <repo> && cd <repo>
python -m venv .venv
.venv/bin/python -m pip install -r requirements.txt     # Linux/麒麟；Windows 为 .venv\Scripts\python
# 或 pip install -e .
# 启动服务（任选其一）
.venv/bin/python -m uvicorn memoryhub.app:app --host 127.0.0.1 --port 8099
# Linux/麒麟： bash scripts/start-memoryhub-service.sh
# Windows：    powershell -File scripts/start-memoryhub-service.ps1
```

### 4.4 系统要求

| 项 | 生产（麒麟） | 开发验证（Windows） |
|---|---|---|
| OS | 银河麒麟 V10/V11 / openKylin 2.x（UKUI） | Windows 10/11 |
| 内核 | Python 3.11+ | 同左 |
| Embedding/向量 | 麒麟 Embedding SDK + Milvus | Mock Embedding + FAISS |
| 控制台 | Qt 5.15、CMake 3.16+、C++17 | Qt 5.15 (msvc2019_64) |

> 环境自检：`python scripts/verify_kylin_environment.py [--mock]` 输出 `retrieval_environment_manifest.json`，覆盖平台 / SDK 可加载性 / 维度 / 依赖版本。

### 4.5 升级、卸载与数据保留

- **数据目录独立**（`~/.local/share/MemoryHub/`），升级保留全部记忆数据；安全密钥首次生成后跨重启复用（【已实现】stable-key 机制），升级不导致审计链失效。
- **卸载**：可保留或清理记忆数据（清理选项【规划中】）。

## 5. 用户如何使用与交互（以最终用户为主）

### 5.1 最终用户：通过 OS Agent 自然语言（主要路径）

记忆能力对最终用户**基本无感**，通过 Agent 对话自然发生：

| 交互 | 发生方式 | 机制 |
|---|---|---|
| **隐式记忆** | 正常对话/操作，Agent 工具轨迹自动沉淀 | Hooks（Claude Code：`PostToolBatch` 累积 + `Stop` 每回合冲刷）/ Plugin（opencode：`session.idle`）→ 构造 `MemoryEvent` → 安全过滤 + 抽取 |
| **显式记住** | 用户说"记住：……" | MCP `memoryhub_write_preference` / `write_knowledge` / `write_event` |
| **显式遗忘** | 用户说"忘掉：……" | MCP `memoryhub_forget`（NL / 范围 / ID 三种定位 + 预览） |
| **记忆感知** | Agent 引用记忆时说明来源 | 检索命中的记忆以 `context_text` 注入 prompt，Agent 自然带出（如"根据你之前的偏好……"） |
| **间接查看/控制** | 用户想核实/删除记忆 | 打开桌面控制台（只读查看 / 删除 / 归档），或让 Agent 调 `memoryhub_list_memories` |

**交互设计要点**：
- 最终用户不直接面对记忆系统 API，面对的是"更懂我的 Agent"；
- 隐式沉淀为主、显式指令为辅，记忆写入零打扰；自动沉淀**事件驱动、失败软着陆**（失败只写日志，不阻塞/不打断对话）；
- 上下文注入量受 `top_k` / `min_confidence` / 场景过滤约束，默认仅注入高置信命中项，控制 token 成本；
- 删除/遗忘走二次确认，记忆状态可回滚（软删除 + 回收站恢复）。

### 5.2 开发者 / 集成方：MCP / REST

- **MCP 12 工具**：读（`search`/`get_context`/`list_memories`/`get_memory`）、写（`write_event`/`write_preference`/`write_knowledge`）、控（`forget`/`feedback`/`resolve_conflict`/`list_conflicts`）、连通性（`health`）——详见[第 6 章](#6-agent-如何调用-memoryhub)。
- **REST**：`/api/memory/*` 全套接口（检索/写入/遗忘/冲突/反馈/生命周期/安全/系统状态），契约见 `docs/INTERFACE.md`。
- **三套现成集成**：Claude Code（插件 + hooks）、opencode（插件）、Qwen-LangGraph（Python 集成包 `integrations/`）。
- **自定义 Agent**：按 `integrations/agents/` 示例注册工具、复用 `schemas_bridge` 校验写入契约。

### 5.3 运维 / 审计：Qt 桌面控制台（21 页 9 模块）

| 模块 | 页面（节选） | 典型操作 |
|---|---|---|
| 总览 | Dashboard | 记忆统计、类型占比、状态分布、事件流、系统状态 |
| 内置终端 | 终端 | 在控制台内唤起 opencode，用自然语言管理记忆 |
| 记忆管理 | 偏好 / 知识 / 事实 | 列表·筛选·详情抽屉·版本链·批量删除·事实候选裁决 |
| 检索与冲突 | 检索测试、冲突中心 | 混合检索 + 上下文预览；新旧冲突对比 + override/merge/coexist 裁决 |
| 遗忘与生命周期 | 精准遗忘、待审查、归档、回收站、健康度、历史、设置 | NL/范围/ID 遗忘预览与执行、状态流转、自动遗忘触发 |
| 安全中心 | 安全总览、用户规则、审计日志、隔离区 | 敏感规则 CRUD（密文）、HMAC 审计验链、REVIEW 放行/丢弃 |
| 系统设置 | 后端状态、参数查看、演示数据工具 | 子系统状态灯、只读配置、清空演示数据 |

## 6. Agent 如何调用 MemoryHub

### 6.1 调用架构

```
┌──────────────── Agent 侧 ─────────────────┐        ┌──────── MemoryHub 内核 ────────┐
│  Agent LLM                                │        │  MemoryHub REST (FastAPI)      │
│   │ tools/call                            │  HTTP  │  /api/memory/*  127.0.0.1:8099 │
│   ▼                                       ├───────▶│  · 安全 Gate + 抽取 + 检索       │
│  memoryhub_mcp（stdio JSON-RPC，12 工具）  │        │  · 偏好/知识/事实写入与索引同步   │
│                                           │        │  · 遗忘 / 冲突 / 生命周期        │
│  Hooks/Plugin（工具轨迹 → MemoryEvent） ───┼───────▶│  /api/memory/events 自动沉淀     │
└───────────────────────────────────────────┘        └────────────────────────────────┘
```

- 读路径与显式写：Agent LLM 通过 MCP 工具按需调用；
- 写路径自动沉淀：Agent 的 hooks/plugin 把会话工具轨迹构造成 `MemoryEvent` 推送给 REST，由内核做安全过滤与三类记忆抽取；
- 两条链路共享同一个正在运行的 MemoryHub REST 服务。

### 6.2 读取时机（何时调用）

MCP Server 在 `initialize` 响应中下发 `serverInstructions`（Claude Code 的 MCP tool search 据此加载）：

> 当问题可能依赖用户的持久偏好、过去的可复用工作流或事实时，**先调用 `memoryhub_search` / `memoryhub_get_context`**；命中记忆以 `context_text` 注入 prompt 后再作答。

检索请求支持按 `user_id`、`scene`、`task_type`、`app`、`memory_types`、`min_confidence` 过滤，命中后由重排序返回 top-k。

### 6.3 写入时机（显式 + 自动）

| 通道 | 触发 | 工具/机制 |
|---|---|---|
| 显式写入 | 用户明确表达"记住 / 忘掉" | `write_preference` / `write_knowledge` / `forget` |
| 自动沉淀（Claude Code） | `PostToolBatch` 每批累积 + `Stop` 每回合冲刷 + `SessionEnd` 兜底 | hooks → `record.py` → `POST /api/memory/events` |
| 自动沉淀（opencode） | `session.idle` 整会话一次 | plugin → 构造 `MemoryEvent` |
| 自记录过滤 | 跳过 MemoryHub 自身工具调用，避免自我写入循环 | `record.py` 内建过滤 |

> 另有 **Qwen-LangGraph 集成**（`integrations/`）：以 Python 集成包调用同一套 REST 能力，工具注册与事件轨迹适配见 `integrations/agents/`。三套集成共用同一个 MemoryHub 服务与同一份记忆。

### 6.4 12 个 MCP 工具清单

| # | MCP 工具 | 用途 | 对应 REST |
|---|---|---|---|
| 1 | `memoryhub_health` | 服务可达性检查 | `GET /api/memory/preferences`（连通性探测） |
| 2 | `memoryhub_search` | 混合检索偏好/知识/事实 | `POST /api/memory/search` |
| 3 | `memoryhub_get_context` | 取可直接注入 prompt 的上下文文本 | `POST /api/memory/context` |
| 4 | `memoryhub_write_event` | 写入 MemoryEvent，触发安全过滤+抽取 | `POST /api/memory/events` |
| 5 | `memoryhub_write_preference` | 显式写偏好并同步向量索引 | `POST /api/memory/memories/preference` |
| 6 | `memoryhub_write_knowledge` | 显式写知识并同步向量索引 | `POST /api/memory/memories/knowledge` |
| 7 | `memoryhub_forget` | 自然语言/范围/ID 精准遗忘 | `POST /api/memory/forget` |
| 8 | `memoryhub_list_memories` | 按类型/场景列出记忆 | `GET /api/memory/preferences|knowledge|facts` |
| 9 | `memoryhub_get_memory` | 取单条记忆详情（含 payload/证据/版本） | `GET /api/memory/{type}/{id}` |
| 10 | `memoryhub_feedback` | update/confirm/reject 反馈 | `POST /api/memory/feedback` |
| 11 | `memoryhub_list_conflicts` | 列待处理冲突 | `GET /api/memory/conflicts` |
| 12 | `memoryhub_resolve_conflict` | override/merge/coexist/pending 裁决冲突 | `POST /api/memory/conflicts/{id}/resolve` |

> 注：`memoryhub_health` 的探测目标是一个轻量接口，**仅用于连通性判断**，不代表对偏好接口的语义依赖。

### 6.5 调用原则

1. **读多写少**：检索/取上下文为主，写入优先走自动沉淀，显式写入仅在用户明确要求时；
2. **安全先于写入**：所有写入过安全门禁（ALLOW / MASK / REVIEW / REJECT），敏感内容不落地原文；
3. **人机协同裁决**：事实候选、冲突由用户或 Agent 显式裁决，不静默覆盖；
4. **按需返回**：`top_k` / `min_confidence` / `max_tool_output_chars` 可控，控制上下文占用。

## 7. 数据、安全与隐私

| 能力 | 说明 | 状态 |
|---|---|---|
| **端侧数据主权** | 记忆数据存于本机（SQLite + 向量索引），不经云端；多用户按 `user_id` 隔离 | 【已实现】 |
| **安全门禁** | 写入前递归扫描，四种处置 ALLOW / MASK / REVIEW / REJECT；`fail_closed` 兜底 | 【已实现】 |
| **用户敏感规则** | 用户自定义敏感词/模式，加密存储（只写不回显）、乐观并发、版本链 | 【已实现】 |
| **审计链** | HMAC 哈希链防篡改，`/audit-logs/verify` 可验链 | 【已实现】（默认关，需开启） |
| **REVIEW 隔离区** | 命中 REVIEW 的内容加密隔离，人工放行或丢弃 | 【已实现】（默认关，需开启） |
| **精准遗忘** | NL / 范围 / ID 三种定位 + 预览 + 级联清理向量/证据/冲突 | 【已实现】 |
| **生命周期自动清理** | 健康度（0.6·时间衰减 + 0.4·使用频率）、自动遗忘（阈值 0.2/0.4/0.6）、等级晋升/过期 | 【已实现】 |
| **存储冗余与一致性** | SQLite ↔ 向量索引同步 + 补偿任务保证最终一致 | 【已实现】 |

> **⚠️ 默认安全水位**：安全门禁 / 用户规则 / 精准遗忘 / 生命周期**默认即生效**；但**审计链与 REVIEW 隔离区当前默认关闭**（`config.yaml` 中 `safety.audit.enabled` / `safety.quarantine.enabled` 为 `false`）。生产部署**必须显式开启**并配置加密密钥（`MEMORYHUB_AUDIT_HMAC_KEY` / `MEMORYHUB_QUARANTINE_KEY`）。开启前，写入事件仍过安全门禁，但不产生可审计的哈希链记录。"默认关"这一策略为待定项（见[第 9 章](#9-风险非目标与未决问题)）。

## 8. 关键设计决策（与主流方案对照）

### 8.1 主流 Agent 记忆方案形态

2024–2026 年主流方案（Mem0 / Letta / LangMem / Zep）的共同形态：

- **记忆服务或 SDK** + 检索 API + Agent 框架集成（工具 / MCP）；
- **混合检索**（语义 + 关键词 + 元数据）作为标配；
- **记忆生命周期**（写入 → 检索 → 更新 → 合并 → 遗忘）显式建模；
- 分发以 **云 API / 自托管 / 开发 SDK** 为主，面向开发者。

### 8.2 对照表

| 维度 | **MemoryHub** | Mem0 | Letta (MemGPT) | LangMem | Zep |
|---|---|---|---|---|---|
| 部署 | **OS 端侧预装 + 独立安装包** | 云 API / 自托管 | 云 / 自托管 | 库（LangChain） | 云 / 自托管 |
| 接入 | **MCP + REST + hooks/plugin** | SDK / API | SDK | LangChain 工具 | SDK / API |
| 记忆模型 | **偏好 / 知识(workflow·case·template) / 事实(S-P-O)** | 通用提取记忆 | 分层自编辑记忆 | 偏好/事实/语义 | 通用 + 时间线 |
| 检索 | **BM25 + 向量 + 元数据加权混合** | 混合检索 | 向量 | 向量 | 混合 + 时序 |
| 生命周期 | **健康度 / 自动遗忘 / 等级晋升** | 更新合并 | 记忆编辑 | 提取更新 | 时间衰减 |
| 多 Agent 共享 | **✓（单一底座 + MCP 多集成）** | ✓ | ✓ | ✓ | ✓ |
| 安全/审计 | **内置门禁 + HMAC 审计链 + 隔离区 + 用户规则** | 合规过滤 | 隐私控制 | — | 企业安全 |
| 目标用户 | **OS 终端用户（间接）+ 开发者** | 开发者 | 开发者 | 开发者 | 开发者 |

### 8.3 关键决策及理由

| # | 决策 | 理由 |
|---|---|---|
| 1 | **端侧部署而非云** | 麒麟 OS 场景对隐私、离线可用、数据主权要求高；端侧推理/存储成本低、延迟低（本地 `127.0.0.1`） |
| 2 | **MCP 标准接入** | MCP 已成为 Agent 工具调用的开放标准，一次实现多 Agent 复用（Claude Code / opencode / 自研），避免为每家框架写专用 SDK |
| 3 | **三类记忆模型** | 偏好（怎么做）/ 知识（如何做：workflow/case/template）/ 事实（是什么：S-P-O）语义互补，各自有独立的抽取、检索与生命周期策略 |
| 4 | **混合检索** | 向量（语义）+ BM25（精确关键词）+ 元数据（scene/task/app），兼顾召回准确性与泛化 |
| 5 | **自动沉淀 + 显式写入双通道** | 低打扰（hooks 自动沉淀）+ 高可控（显式指令、门禁、裁决），平衡"少打扰用户"与"记忆可信" |
| 6 | **安全内置为一等公民** | 门禁 + 审计链 + 隔离区 + 用户规则内建于内核而非外挂，记忆系统天然需要防泄露与可追责 |

### 8.4 已知局限与差距（相对竞品）

对照表侧重差异点，也应如实看到短板：

| 维度 | 相对竞品的差距 |
|---|---|
| 生态成熟度 | Mem0/Zep 已有大量生产客户与社区、云托管与多语言 SDK；MemoryHub 目前以 Python / 麒麟自托管为主 |
| 开发者上手 | 竞品提供托管 API 与成熟 SDK，分钟级接入；MemoryHub 需自部署服务，生产装配尚未一键化 |
| 评测与基准 | 检索评测已有基线；偏好/冲突评测、长会话记忆压力测试尚未完成 |
| 云能力 | 无云托管/多租户；跨设备同步为可选规划项（若做，需重新定义"端侧"边界） |
| 真实 LLM 抽取 | 生产抽取依赖真实 LLM 的质量调优，当前为规则/降级路径 |

## 9. 风险、非目标与未决问题

### 9.1 主要风险

| # | 风险 | 影响 | 缓解 |
|---|---|---|---|
| 1 | **OS 预装依赖 OEM/商业合作**：随麒麟 OS 出厂并非纯技术问题 | 主分发渠道若延后，用户获取受影响 | P1 先交付独立安装包；预装作为商业推进项（见 9.3） |
| 2 | **真实 LLM 抽取质量未验证**：当前抽取为规则/降级路径 | 记忆质量与评测可信度受影响 | 接入真实 LLM 后做抽取评测与调优（P2） |
| 3 | **生产栈（麒麟 SDK/Milvus）未全面验证**：开发栈为 Mock+FAISS | 生产性能/兼容性未知 | 环境自检脚本 + 麒麟环境基准测试（P2） |
| 4 | **安全默认水位低**：audit/quarantine 默认关 | 数据敏感场景审计缺失 | 生产 profile 默认开启（P2） |
| 5 | **记忆被误沉淀/误引用**：自动沉淀可能记录噪声或错误偏好 | 用户体验与信任受损 | 安全门禁 + 置信度 + 用户裁决 + 可一键遗忘 |
| 6 | **上下文注入成本**：每回合注入记忆占用 token/上下文 | Agent 回答质量受影响 | `top_k` / `min_confidence` / 场景过滤 + 缓存 |

### 9.2 非目标（Non-Goals）

- **不做云端托管/多租户 SaaS**（跨设备同步为可选规划项，若做需重新定义端侧边界）；
- **不做 Agent 本体**：MemoryHub 不提供对话界面，依赖麒麟 OS 上已有的 Agent 作为入口；
- **不做记忆语义理解的兜底**：最终记忆质量取决于所接 LLM 的抽取能力，MemoryHub 提供的是存储/检索/生命周期/安全基座；
- **不替代向量数据库**：向量索引可插拔（FAISS / Milvus），由部署环境决定。

### 9.3 未决问题（Open Questions）

| # | 问题 | 当前倾向 |
|---|---|---|
| 1 | 麒麟 OS 是否/如何出厂预装 Agent？预装哪个？ | 外部依赖，待与平台方确认 |
| 2 | OS 预装以何种商业/合作形式落地？ | 待定（见 9.1#1） |
| 3 | audit/quarantine 默认开启 or 保持默认关？ | 倾向生产 profile 默认开启 |
| 4 | 密钥管理方案：env var / 系统钥匙串 / TPM？ | 当前 env var，待定 |
| 5 | 跨设备同步是否纳入路线？ | P3 可选 |
| 6 | 多用户隔离粒度：仅 `user_id` 还是需要权限模型？ | 当前 `user_id`，待定 |

### 9.4 验收标准 / 成功度量

| 维度 | 度量 | 目标 |
|---|---|---|
