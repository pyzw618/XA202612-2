> 莫耀华 | 2026-07-20

## 一、页面总览

共 7 个页面，覆盖记忆管理的全部环节：

| 页面      | 路由             | 功能                             |
| --------- | ---------------- | -------------------------------- |
| Dashboard | `/`            | 记忆总览看板                     |
| 偏好管理  | `/preferences` | 偏好记忆列表 + 查看详情 + 版本链 |
| 知识管理  | `/knowledge`   | 知识记忆列表 + 查看详情          |
| 冲突处理  | `/conflicts`   | 冲突列表 + 手动解决              |
| 检索测试  | `/search`      | 输入查询，展示召回结果           |
| 遗忘管理  | `/forget`      | 自然语言遗忘 + 遗忘历史          |
| 评测报告  | `/evaluation`  | 评测指标展示                     |

---

## 二、各页面功能

### 1. Dashboard

- 展示记忆总数、偏好数量、知识数量、待处理冲突数
- 最近检索延迟折线图
- 各类型偏好/知识占比饼图

### 2. 偏好管理

- 表格展示所有偏好记忆（类型、内容、置信度、场景、状态）
- 支持按场景、状态筛选
- 点击展开：版本链时间线、证据链列表
- 支持手动修改状态（active/archived）

### 3. 知识管理

- 表格展示所有知识记忆（类型、名称、步骤、工具链、成功率）
- 支持按类型筛选（workflow/case/template）
- 点击展开：查看详细步骤和关联工具

### 4. 冲突处理

- 卡片式展示冲突（旧记忆 vs 新记忆）
- 展示冲突字段、冲突类型、系统建议决策
- 用户可手动选择：覆盖 / 合并 / 并存 / 待确认

### 5. 检索测试

- 输入框：模拟用户查询
- 选择场景（scene/task_type）
- 展示召回结果列表（偏好 + 知识 + 得分）
- 显示检索延迟

### 6. 遗忘管理

- 输入框：自然语言遗忘指令
- 展示匹配到的目标记忆
- 确认后执行遗忘，展示删除结果
- 下方：遗忘操作历史记录

### 7. 评测报告

- 四项核心指标卡片（偏好准确率、检索召回率、响应延迟、冲突正确率）
- 历史评测报告列表
- 点击查看详细评测数据

## 三、API 对应关系

基于 [docs/INTERFACE.md](../docs/INTERFACE.md) 和 [memoryhub/adapter/api.py](../memoryhub/adapter/api.py)：

| 页面      | 调用的 API                                                                        |
| --------- | --------------------------------------------------------------------------------- |
| Dashboard | `GET /preferences` `GET /knowledge` `GET /conflicts`                        |
| 偏好管理  | `GET /preferences` `GET /preferences/{id}` `GET /preferences/{id}/versions` |
| 知识管理  | `GET /knowledge` `GET /knowledge/{id}`                                        |
| 冲突处理  | `GET /conflicts` `POST /conflicts/{id}/resolve`                               |
| 检索测试  | `POST /search` `POST /context`                                                |
| 遗忘管理  | `POST /forget` `GET /forget/history`                                          |
| 评测报告  | `POST /evaluate/{task_name}` `GET /evaluate/reports`                          |

**核心接口（队长确认的 4 个）：**

- `POST /api/memory/search` — 检索记忆
- `POST /api/memory/context` — 获取可注入 prompt 的记忆文本
- `POST /api/memory/events` — 写入事件（本页面不直接调，由 OS Agent 调用）
- `POST /api/memory/forget` — 精准遗忘

## 四、技术选型讨论

### 方案 A：Vue 3 + Element Plus

**优势：**

- 开发效率高，Element Plus 组件丰富（表格、表单、对话框、图表）
- 和 FastAPI 后端天然匹配（HTTP + JSON）
- 部署简单，`npm run build` 后静态文件即可

**劣势：**

- 浏览器运行，无法使用系统原生能力（托盘、通知、D-Bus）
- 作为比赛作品，技术亮点不够突出

### 方案 B：PyQt6 / PySide6

**优势：**

- 麒麟桌面本身就是 Qt 体系，原生窗口、系统托盘、D-Bus 通信
- 比赛答辩时「原生麒麟桌面应用」是加分项
- 可调用麒麟 embedding SDK 的 C 接口（ctypes）

**劣势：**

- 开发效率低于 Vue 3（手写布局、信号槽）
- 打包部署复杂（PyInstaller）

## 五、特殊需求（影响技术选型）

以下需求如果确认需要，会倾向 PyQt6：

1. **系统托盘通知**：有新冲突时右下角弹窗提醒用户
2. **离线缓存**：本地 SQLite 缓存 API 数据，断网也能查看
3. **文件选择器**：导入/导出评测数据时调用系统文件对话框
4. **D-Bus 通信**：与麒麟 OS Agent 进程直接通信（非 HTTP）

如果不做以上功能，Vue 3 完全够用。
