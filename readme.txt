一.memory_store.py————整个记忆系统的“Mock 数据存储中心（数据库底座）”
1.1 主要工作目的：把原始文字、SDK翻译出来的数字向量、以及时间标签，统统打包存起来并进行管理。
1.2 核心数据结构————MemoryRecord类
    1.2.1 记录哪些内容
        id: 给每一条记忆生成一个不重复的12位字符串。未来你想执行**“精准遗忘操作”**（赛题要求5），就是靠这个ID去指名道姓地删除。
        content: 存用户说的话（比如：“我习惯把下载文件放在D盘”）。BM25关键词检索就是对着这个字段查的。
        embedding: 这里就是留给麒麟 Embedding SDK 的坑位！SDK算出来的那个很长的数组，就塞进这里。FAISS向量检索就是对着这个字段查的。
        created_at: 自动记录这片记忆是几点几分产生的。未来你做**“中短期记忆淘汰流转”**（赛题要求6），比如“删除7天前的短期记忆”，就是靠对比这个时间戳！
        metadata: 这是一个极度灵活的字典（类似贴纸）。你可以往里面塞 {"type": "偏好", "level": "短期", "source": "终端命令"}。以后你可以根据标签过滤搜索结果。
1.3 存储管理结构————MemoryStore类
    1.3.1 初始化与增加
        目前用一个列表当假数据库
    1.3.2 查找
        当 FAISS 向量库或者 BM25 告诉你“ID为 1234 的记忆最匹配”时，你通过这个方法，把 ID=1234 对应的原始文本 content 拿出来扔给大模型。
    1.3.3 删除
        找到指定的id，把它从档案柜里抽出来销毁

二.mock_embedding.py
2.1 主要工作目的：伪造了一个“麒麟 Embedding 翻译官”。你给它输入一段文字，它会假装思考 0.1 秒，然后吐出一个包含 768 个小数的随机数组（向量）
2.2 确定性随机_deterministic_seed
    通过哈希函数，使得相同文本无论调用多少次，每一次生成的随机数组都是一模一样的
2.3 批量处理embed_batch
    模拟了硬件底层的“批处理加速”。处理 1 条和处理 50 条，系统只消耗一次 100ms 延迟。这提醒你：在实际写代码时，尽量把多条记忆打包送给 SDK 处理

三.search_engine.py
3.1 主要工作目的：怎么在端侧轻量化环境中，实现高召回率（≥85%）的检索？————混合检索（Hybrid Search）
3.2 简易分词器 (_simple_tokenize)
    把一整句话切成一个个词或字，这是给 BM25 用的。
3.3 BM25 检索器 (BM25Retriever)
    3.3.1 底层依赖： 用了 rank_bm25 这个非常轻量的 Python 库。
    3.3.2 核心逻辑：
        index(): 遍历库里所有的文字，建立“倒排索引”（统计每个词在哪些句子里出现过，出现了几次）。
        search(): 算出一个 TF-IDF 升级版的分数。匹配的关键词越多、这个关键词越稀有，分数就越高（比如 15.6 分，22.1 分）。分数没有上限。
3.4 FAISS 检索器 (FaissRetriever) —— 端侧轻量的关键
    3.4.1 底层依赖： Meta（Facebook）开源的 faiss-cpu。这是目前单机端侧跑得最快的向量检索引擎，占内存极小
    3.4.2 提高检索速度的关键之处————两个长度为 1 的向量算内积，结果就等于余弦相似度
        faiss.normalize_L2(np_vectors)
        self._index = faiss.IndexFlatIP(self.dim)
        向量检索通常看“余弦相似度”（计算两个向量之间的夹角）。但是直接算余弦相似度比较慢。
        它先对所有向量做了一次 L2 归一化（把所有向量的长度都拉成 1），然后使用 IndexFlatIP（内积计算）。分数范围固定在 [-1, 1] 之间（越接近1越相似）。
3.5 统一搜索入口：MemorySearchEngine类
    3.5.1 BM25和FAISS分数统一
        把 BM25 的分数压缩到 [0, 1] 之间。（最高分算1分，最低分算0分，中间的按比例算）。
        把 FAISS 的分数从 [-1, 1] 映射到 [0, 1] 之间（公式：(score + 1.0) / 2.0）。
        加权计算： 默认配置是 bm25_weight = 0.3（关键词占30%权重），faiss_weight = 0.7（语义占70%权重）。计算出最终得分！
        按最终得分从大到小排序，提取 Top-K 返回给大模型。
